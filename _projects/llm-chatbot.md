## 프로젝트 개요

망분리 환경에서 활용 가능한 내부 LLM 챗봇 개발을 통해 개발 효율성 증대

챗봇 서비스 도입 이후, 요건 분석 소요 시간을 평균 5일에서 2일로 **60% 이상 단축**하고, 확보된 리소스를 **테스트 단계에 집중 투자하여 서비스 안정성을 강화** **(25년 발생 장애 0건)**

**기간**: 
- 소스코드 챗봇: 2025.05 ~ 2025.08 (4개월)
- 테스트 헬퍼 챗봇: 2025.01 ~ 진행중

## 역할

- 소스코드 챗봇 개발
- 테스트 헬퍼 챗봇 UI 개발
- 테스트 헬퍼 챗봇 승인계 전문 생성 개발

## 문제점

- 보안 환경 특성 상 개발망에서 외부 AI 활용 불가로 인한 리소스 낭비
- LLM 답변 시간이 긴 경우, 응답 시간 지연인지 응답 에러인지 확인이 어려움
- 전송 전문을 그대로 LLM에게 전달 시 프롬프트의 전달성이 낮아지는 문제
- 전체 전문 정보 + 소스코드 + 테스트 히스토리 모두 전달시 LLM Context Length(토큰) 초과 이슈 발생

## 해결 방법

- vLLM(gpt-oss120b)을 활용해 보안 이슈 없는 LLM 서비스 도입
- **Streaming Response:** vLLM에 스트리밍 응답 기능을 추가하여 UX 개선(실시간 응답 진행)
- **전처리 파이프라인:** 전문을 JSON으로 구조화 및 요약하여 토큰 사용량 최적화 및 LLM 이해도 향상
    - 단순 전문 데이터뿐만 아니라 필드별 의미(설명, 명칭)를 포함한 JSON 객체로 구조화하여 프롬프트 전달성을 강화
    - 전체 테스트 히스토리를 전송하는 대신, UI 상에서 기준이 되는 샘플 케이스를 첨부받아 이를 보완/확장하는 방식으로 프롬프트 시나리오를 경량화

## 결과

- 망분리 환경에서 LLM을 활용한 검색을 가능하도록 하여 개발 편의성 향상
- 요건 분석 및 레거시 코드 파악 시간 **60% 단축** (5일 → 2일)
- 자가 테스트의 확증 편향으로 놓치기 쉬운 임계치 오류를 방지(경계값 테스트 등에 주로 활용)
    - 사례: 유량 계산 로직 정밀도 테스트 중, AI가 제시한 극한 값 케이스를 통해 필드 허용 자릿수(7자리)와 구현된 로직(6자리) 간의 불일치를 발견
    → 이를 통해 개발자의 육안 검증 한계를 보완하고 휴먼 에러를 사전 차단
