## 프로젝트 개요

수동으로 진행되던 테스트 서버 배포 및 검증 과정을 **웹 기반 자동화 시스템**으로 전환하여 서비스 배포 소요 시간 **86% 단축(15분 → 2분)**

**기간**: 2024.12 ~ 2025.02 (3개월)

## 역할

- 배포 후 자동 검증(Health Check) 및 채널 전환 웹 서비스 설계/개발
- 서버 기동 직후 지연 방지를 위한 Self-Warm-up 로직 구현

## 문제점

- 서버 재기동 직후 첫 거래 시, 클래스 로딩 및 캐시 미적재(Heap Memory)로 인한 **응답 지연 발생**
- 배포 시마다 개발자가 서버에 직접 접속(SSH)하여 Command로 채널을 전환해야 했으며, **재기동 대기 → 테스트 → 전환** 과정에 **건 당 15분 이상 소요**
- 휴먼 에러에 의한 검증 누락으로 잦은 테스트 실패가 발생, 유관 부서(QA 및 현업담당자)의 업무 지연 및 클레임 지속 발생

## 해결 방법

- **JVM Warm-up 자동화:** 재기동 후 실 트래픽 유입 전, **자동으로 최초 거래를 내부 생성**하여 핵심 데이터를 메모리(Heap)에 적재, 첫 거래 지연 이슈 해결
- **컨테이너 스위칭 Web UI 개발:** 서버 직접 접속 없이 웹에서 클릭 한 번으로 채널(Container)을 전환하는 **대시보드 구축**, CLI 의존성 제거
- **배포 파이프라인 자동화:** **서버 기동 확인 → 주요 카드사/서비스 승인·취소 루프 테스트 → 성공 시 자동 채널 전환**으로 이어지는 **배포 프로세스** 구현

## 결과

- **배포 리드타임 86% 단축:** 기존 15분 소요되던 작업이 **2분 내외로 단축**
- **안정성 강화:** 전수 테스트 통과 시에만 트래픽을 받는 **Safety Check** 도입으로 배포 실패/오류 원천 차단
