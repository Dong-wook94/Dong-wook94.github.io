## 프로젝트 개요

데이터 손실 및 타임아웃이 잦던 기존 망취소 방식 및 시스템 전면 재설계

수기 망취소 업무 100% 자동화 → 운영공수 연 17시간 절약, 시스템 안정성 강화 (월평균 100건 → 0건)

**기간**: 2023.12 ~ 2024.03 (4개월)

## 역할

- 통신 구간 내 요청 전문 적재 개발
- 망취소 적재 & 전송 구조 설계

## 문제점

- 기존 로직은 '외부 인터페이스↔원천사' 구간만 커버하여, **'내부 승인시스템↔외부 인터페이스'** 구간 장애 시 대응 불가
- 원천사/은행 지연 발생 시, 지정된 스레드(Thread) 자원 고갈로 인해 상위 큐(Queue) 대기 시간이 길어지며 **내부 구간(내부 승인시스템↔외부 인터페이스) 타임아웃 빈번히 발생**
- **데이터 덮어쓰기(Overwrite) 버그:** 기존 테이블이 Upsert 방식이고 PK가 '거래 Key' 하나로만 구성되어, 다중 구간 로그 적재 시 **마지막 구간 데이터만 남고 이전 이력 소실**
- **바이너리 데이터 손실:** ISO8583 규격의 Hex 데이터를 String으로 변환하여 저장하는 과정에서 일부 **바이너리 값 변형 및 데이터 깨짐** 현상 발생

## 해결 방법

- **정밀한 원인 분석 (with DBA팀):** 소스 코드 상으로는 적재 로직이 존재함에도 데이터가 없는 원인을 밝히기 위해, **DBA팀에 협업 요청하여 임시 Trigger 및 History 테이블을 생성**, Upsert로 인한 데이터 덮어쓰기 현상을 규명
- **복합 키 설계:** PK를 **[거래 Key + 구간 정보(Step ID)]**로 재설계하여, 단일 거래 내에서 발생하는 다중 구간의 망취소 이력을 모두 적재하도록 개선
- 전문 데이터 무결성 확보 및 오변환 해결을 위해 IC / MS 규격에 공통 대응 가능한 구조로 설계
    - 자사 내부 정보를 담은 Header와 원천사 전송용 Body(ISO8583)를 분리
    - 적재 후 전송 담당 개발자에게 개선 협업을 요청하여, Binary 속성의 Body 데이터는 **Base64 인코딩 후 저장**하도록 변경 → 인코딩 호환 문제로 인한 데이터 손실 원천 차단

## 결과

- **업무 자동화:** 분기별 평균 100건 이상 이상 발생하는 수기 망취소 업무 **100% 자동화**
- **민원 감소:** 카드사 및 가맹점 **망취소 누락 관련 이슈 제기 작년 대비 90% 감소 (연평균 10건 → 1건)**
- **안정성 확보:** 전문 데이터 손실 이슈 100% 해결 및 복수 구간 이력 누락 **0건**
